# CLAUDE.md

Entry point for Claude Code. **This file only points; it does not duplicate.** Conventions live in `AGENTS.md`, and the project rule is that no information is maintained in two state files at once — if something here starts drifting from the file it points at, delete it here.

## Read these first

| File | What it holds | Volatility |
|---|---|---|
| `AGENTS.md` | All conventions: voice, style checklist, spine installation, figures, logging, source-of-truth rules | Stable — 6 commits in 5 weeks |
| `HANDOFF.md` | Current state and immediate next actions, nothing else | Rewritten every session — 147 commits in the same period |
| `PROJECT_BACKLOG.md` | Durable deferred work needing a decision | Slow |
| `GPT_project_log.md` | Completed-work history, **newest entries at the top** | Append at top only |

`HANDOFF.md` is a baton, not a rulebook. Read it, act, and rewrite it — do not append to it or treat it as settled convention.

## Before drafting or converting chapter prose

Do not draft first. Run `pipeline/spine-seed-protocol.md`: count the chapter's own Layer 3 threads in its source, draft per-section seeds, and get the framing decisions back from the instructor before writing prose. Drafting straight from the Layer 3 notes makes those decisions silently and produces a chapter the instructor has to argue with as prose rather than as a lens.

`pipeline/spine-seed-prompt.md` is the paste-ready starting prompt for that pass. `pipeline/ch11-spine-seeds.md` is the worked example.

## Working notes

- **Source of truth is `source/chapters/*.md`.** `docs/chapters/*.html` is generated by `pipeline/build_chapter_html.mjs`; do not patch it directly.
- **Stage exact paths. Never `git add .`.**
- **If your shell is a sandbox with this repo mounted (Cowork), do not run `git add`, `git commit`, or `git update-ref` at all.** The mount can *create* lock files inside `.git/` but is not permitted to *unlink* them, so index and ref operations leave `.git/index.lock` and `.git/HEAD.lock` behind. Those block every subsequent git command — for the agent *and* the instructor — until he deletes them by hand on Windows. `GIT_INDEX_FILE` workarounds do not reliably avoid this and can strand an unreferenced commit object. Read-only commands (`git log`, `git status`, `git diff`, `git show`) are safe. Write the files, list the exact paths, and let the instructor stage, commit, and push. A native shell (Claude Code) has none of this problem.
- **The instructor reads Word, not Markdown.** Anything intended for his review goes through `pipeline/build_line_edit_docx.py` into `line-edit-packets/`, not as a diff or a `.md`.
- Verify before claiming: `python pipeline/lint_chapters.py` for structure, and check every in-text citation against the reference list — that check has caught real errors.
